## 1. Introduction to AI

อ้างอิง: M1 หน้า 5–16, 18–21 และ 26–35

### AI คืออะไร

Artificial Intelligence คือการสร้างระบบที่รับรู้ ให้เหตุผล วางแผน และกระทำเพื่อแก้ปัญหา แนวคิดในสไลด์แบ่งเป็น 4 มุมมอง:

| มุมมอง | ใจความ |
|---|---|
| Think like a human | จำลองวิธีคิดของมนุษย์ |
| Act like a human | แสดงพฤติกรรมคล้ายมนุษย์ เช่น การสนทนา |
| Think rationally | ใช้ตรรกะและเหตุผลอนุมานข้อสรุป |
| Act rationally | เลือกการกระทำที่เหมาะกับเป้าหมายและข้อมูลที่มี |

รายวิชานี้เน้น **สร้าง narrow AI agent ที่กระทำอย่างมีเหตุผล** เพื่อแก้ปัญหาเฉพาะ

- **Narrow AI:** ทำงานเฉพาะด้าน เช่น เล่นหมากรุกหรือจำแนกภาพ
- **AGI:** แนวคิดระบบที่เรียนรู้และทำงานทางปัญญาได้กว้างคล้ายมนุษย์
- **Superintelligence:** แนวคิดระบบที่มีความสามารถทางปัญญาสูงกว่ามนุษย์อย่างมาก

### AI, ML, DL ต่างกันอย่างไร

**DL ⊂ ML ⊂ AI**

- **AI:** กรอบใหญ่ของการสร้างระบบอัจฉริยะ รวมถึง search และ logic
- **Machine Learning:** เรียนรู้จากตัวอย่างหรือประสบการณ์
- **Deep Learning:** การเรียนรู้ด้วย neural network หลายชั้น
- **Supervised learning:** มี input และคำตอบกำกับ เช่น classification และ regression
- **Unsupervised learning:** ไม่มีคำตอบกำกับ เช่น clustering
- **Reinforcement learning:** เรียนรู้จากการกระทำและผลตอบแทน

### Intelligent agent

วงจรพื้นฐานคือ **สิ่งแวดล้อม → percept → agent → action → สิ่งแวดล้อม**

ตัวอย่างรถอัตโนมัติ: percept = คนกำลังข้ามถนน; action = ชะลอหรือหยุด; objective = ไปถึงจุดหมายอย่างปลอดภัย

**Rationality:** เลือกการกระทำให้ได้ผลที่ดีที่สุดตามเกณฑ์ที่กำหนด หากมีความไม่แน่นอนให้พิจารณา expected utility ส่วน **bounded rationality** คือการตัดสินใจภายใต้ข้อจำกัดของความรู้ เวลา และกำลังคำนวณ การตัดสินใจมีเหตุผลไม่ได้แปลว่าจะรู้อนาคตหรือสำเร็จทุกครั้ง

### Turing Test และข้อวิจารณ์

Turing Test พิจารณาการแสดงพฤติกรรมสนทนาคล้ายมนุษย์ ความสามารถที่เกี่ยวข้อง ได้แก่ NLP, knowledge representation, automated reasoning และ machine learning

ข้อวิจารณ์: คนอาจถูกหลอกได้ง่าย พฤติกรรมเหมือนมนุษย์ไม่ได้พิสูจน์ว่าเข้าใจ และระบบที่มีประโยชน์ไม่จำเป็นต้องเลียนแบบมนุษย์ทุกอย่าง

### ประวัติและศัพท์แนวคิดที่ควรรู้

- จุดอ้างอิงในสไลด์: Turing (1950), ช่วง AI winter, การเติบโตของ deep learning, Transformer (2017) และ generative AI
- ปัจจัยสนับสนุนความก้าวหน้า: ข้อมูลมากขึ้น ฮาร์ดแวร์/GPU ดีขึ้น และวิธีเรียนรู้/optimization พัฒนา
- **Moravec’s paradox:** งานใช้เหตุผลเชิงสัญลักษณ์บางอย่างทำให้คอมพิวเตอร์เก่งได้ง่ายกว่างานรับรู้และเคลื่อนไหวที่มนุษย์ทำเป็นธรรมชาติ
- **AI effect:** เมื่องานหนึ่งทำได้ดีด้วยเครื่องจักร คนมักเลิกมองว่างานนั้นต้องใช้อัจฉริยะ

### Ethics และ Safety

## 2. Search: BFS และ DFS

อ้างอิง: M2 หน้า 2, 6–11, 16–19 และ 23–32

### องค์ประกอบของปัญหาค้นหา

1. **State space:** สถานะที่เป็นไปได้
2. **Initial state:** จุดเริ่มต้น
3. **Successor function/actions:** จากสถานะนี้ไปไหนได้บ้าง
4. **Cost:** ต้นทุนของการกระทำ
5. **Goal test:** ตรวจว่าถึงเป้าหมายหรือยัง

**Solution** คือลำดับการกระทำที่พา initial state ไปสู่ goal ส่วน **optimal solution** คือลำดับที่มีต้นทุนรวมต่ำที่สุด

**State-space graph:** สถานะหนึ่งเป็นโหนดเดียว แต่ **search tree:** สถานะเดียวอาจปรากฏหลายโหนด เพราะเกิดจากคนละเส้นทาง จึงควรติดตามสถานะที่เคยพบเพื่อป้องกันวนซ้ำ

### เปรียบเทียบ

ให้ b = จำนวนลูกต่อโหนด, d = ความลึกของคำตอบตื้นสุด, m = ความลึกสูงสุด

| ประเด็น | BFS | DFS |
|---|---|---|
| หลักการ | ขยายโหนดตื้นที่สุดก่อน | ขยายโหนดลึกที่สุดก่อน |
| โครงสร้าง | Queue, FIFO | Stack, LIFO หรือ recursion |
| Complete | ใช่ เมื่อ b มีขอบเขตและมีคำตอบที่ความลึกจำกัด | ไม่รับประกันในต้นไม้ลึกไม่สิ้นสุด; กราฟจำกัดที่ตรวจซ้ำครบค้นหาได้ |
| Optimal | ใช่เมื่อ cost ของทุกก้าวเท่ากัน | ไม่รับประกัน |
| เวลาแบบต้นไม้ | O(b^d) ตาม convention ในสไลด์ | O(b^m) |
| พื้นที่ frontier แบบต้นไม้ | O(b^d) | O(bm) |
| ข้อเด่น | เหมาะเมื่อคำตอบอยู่ตื้น ต้องการก้าวน้อยสุด | ใช้ frontier น้อยเมื่อเดินตามกิ่งลึก |
| ข้อจำกัด | เก็บโหนดจำนวนมาก | อาจหลงกิ่งลึก ได้คำตอบยาว |

หมายเหตุเรื่อง Big-O: ตำราที่นับการสร้างลูกของชั้นคำตอบด้วยอาจเขียน BFS เป็น O(b^(d+1)) ให้ยึด convention ของโจทย์ ส่วน DFS ที่เก็บ visited ครบกราฟจะใช้พื้นที่เพิ่มตามจำนวนสถานะ ไม่ใช่ O(bm) สำหรับข้อมูลทั้งหมดเสมอ

### ตัวอย่างฝึกเพิ่ม: ไล่ลำดับ

```text
        S
      /   \
     A     B
    / \   / \
   C   D E   G
```

กำหนดตรวจลูกซ้ายไปขวาและตรวจ goal เมื่อดึงออกจาก frontier:

- BFS: S → A → B → C → D → E → G
- DFS: S → A → C → D → B → E → G
- หากใช้ stack แล้วต้องการสำรวจซ้ายก่อน ให้ push ลูกขวาก่อนลูกซ้าย
- **ลำดับโหนดที่สำรวจ** ต่างจาก **เส้นทางคำตอบ**: ในตัวอย่างเส้นทางคำตอบคือ S → B → G

### โครงร่าง BFS ที่ต้องจำ

```text
ใส่ start ใน queue และทำเครื่องหมายว่าเคยพบ
ขณะที่ queue ไม่ว่าง:
    ดึงตัวหน้าสุด
    ถ้าเป็น goal: คืนเส้นทาง
    สำหรับ successor ที่ยังไม่เคยพบ:
        บันทึก parent และทำเครื่องหมายว่าเคยพบ
        ใส่ท้าย queue
```

เปลี่ยนเป็น DFS ได้โดยดึงตัวท้ายของ stack แต่ลำดับลูกและวิธีทำเครื่องหมาย visited อาจทำให้ลำดับสำรวจต่างกัน ต้องระบุให้ชัดในข้อสอบ

**กับดัก:** BFS หาเส้นทาง “จำนวนก้าวน้อยสุด” เมื่อทุกก้าวต้นทุนเท่ากัน หากถนนแต่ละเส้นมีระยะทางต่างกัน BFS ไม่รับประกันระยะทางรวมน้อยสุด

## 3. 8-Puzzle และ A*

อ้างอิง: M3 หน้า 3–9, 11–17 และ 20–27

### การแทนสถานะ

กระดาน 3×3 มีเลข 1–8 และช่องว่างใช้ 0 เก็บแบบ tuple เพื่อให้ hashable และใช้ใน set/dict ได้ เช่น:

```python
state = (1, 0, 2,
         3, 4, 5,
         6, 7, 8)
goal = tuple(range(9))  # เป้าหมายตามสไลด์นี้
```

**อย่าสับสนเป้าหมาย:** สไลด์นี้ใช้ `(0,1,2,3,4,5,6,7,8)` โจทย์อื่นอาจใช้ `(1,2,3,4,5,6,7,8,0)` สูตรหาตำแหน่งเป้าหมายต้องตรงกับโจทย์

ตำแหน่ง index i แปลงเป็น `row = i // 3`, `col = i % 3` และแปลงกลับด้วย `i = 3*row + col`

การสร้าง successor: หาตำแหน่ง 0 → ลองเลื่อนบน/ล่าง/ซ้าย/ขวา → ตรวจแถวและคอลัมน์อยู่ใน 0–2 → สลับ 0 กับช่องข้างเคียง → เก็บสถานะใหม่

```python
def get_moves(state):
    i = state.index(0)
    r, c = divmod(i, 3)
    result = []
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        nr, nc = r + dr, c + dc
        if 0 <= nr < 3 and 0 <= nc < 3:
            j = nr * 3 + nc
            nxt = list(state)
            nxt[i], nxt[j] = nxt[j], nxt[i]
            result.append(tuple(nxt))
    return result
```

### Manhattan distance

ระยะของแผ่นหนึ่ง = `|แถวปัจจุบัน - แถวเป้าหมาย| + |คอลัมน์ปัจจุบัน - คอลัมน์เป้าหมาย|` แล้วรวมทุกแผ่นที่กำหนด

**เงื่อนไขเฉพาะของเอกสารนี้:** หน้า 20 ให้รวมช่องว่าง 0 ในผลรวมด้วย หากโจทย์สั่ง “ตามสไลด์” ให้แสดงการคำนวณตามนั้น

**ข้อควรเข้าใจทางทฤษฎี:** Manhattan สำหรับ 8-Puzzle ที่ใช้รับประกัน optimality ของ A* โดยทั่วไปไม่นับช่องว่าง เพราะหนึ่งก้าวทำให้ทั้ง 0 และแผ่นหนึ่งขยับ การนับทั้งคู่จึงอาจประเมินสูงกว่าต้นทุนจริง

ตัวอย่างจาก state ด้านบน: สลับ 0 กับ 1 เพียงครั้งเดียวก็ถึง goal ดังนั้นต้นทุนจริงที่เหลือ = 1; ไม่นับ 0 ได้ h = 1; นับ 0 ได้ h = 2 ซึ่งมากกว่า 1 จึงไม่เป็น admissible heuristic ในตัวอย่างนี้

### A* Search

**f(n) = g(n) + h(n)**

- g(n): ต้นทุนจริงจาก start มาถึง n
- h(n): ประมาณต้นทุนจาก n ไป goal
- f(n): ประมาณต้นทุนรวมของเส้นทางผ่าน n
- เลือกโหนดใน frontier ที่ f ต่ำสุดด้วย priority queue เช่น `heapq`

ตัวอย่างฝึกเพิ่ม: A มี g=3,h=4 → f=7; B มี g=5,h=1 → f=6 ดังนั้นขยาย B ก่อน แม้ g ของ B สูงกว่า

ใน graph search ควรเก็บ `best_g[state]` ถ้าพบเส้นทางใหม่ที่ g ต่ำกว่าเดิมให้ปรับข้อมูลและนำกลับเข้า frontier การเจอสถานะซ้ำไม่ได้แปลว่าทิ้งได้ทุกครั้ง

**เงื่อนไขสำคัญ:** admissible หมายถึง h ไม่เกินต้นทุนจริงที่เหลือ; consistent หมายถึง `h(n) ≤ cost(n,n') + h(n')` หากใช้ heuristic ที่ admissible และจัดการเปิดสถานะใหม่อย่างถูกต้อง A* จึงรับประกันต้นทุนดีที่สุดภายใต้เงื่อนไขมาตรฐาน หากปิดสถานะถาวรโดยไม่ reopen ต้องระวังเงื่อนไข consistency ด้วย

**ศัพท์ที่ต้องแยก:** feedforward/backpropagation เป็นของ neural network; frontier/backtracking ในบทนี้เป็นกระบวนการค้นหา

## 4. Game Tree: Minimax และ Alpha-Beta

อ้างอิง: M4 หน้า 2–18 และ 19–24

### Minimax

ใช้เลือกการเดินในเกมคู่แข่ง เช่น เกมสองฝ่ายที่มี utility ตรงข้ามกัน โดยสมมติว่าคู่แข่งเลือกอย่างดีที่สุดเช่นกัน ค่าทั้งหมดอ่านจากมุมของ MAX

- **MAX:** เลือกค่ามากที่สุดจากลูก
- **MIN:** เลือกค่าน้อยที่สุดจากลูก
- เริ่มจากค่าใบ ย้อนกลับขึ้นมาสลับ MAX/MIN จนถึง root
- หากค้นไม่ถึงสถานะจบ จะจำกัดความลึกและใช้ evaluation function ประเมินตำแหน่ง

ตัวอย่างจากสไลด์:

```text
D = max(-1, 4) = 4
E = max(2, 6)  = 6
F = max(-3,-5) = -3
G = max(0, 7)  = 7
B = min(D,E)  = 4
C = min(F,G)  = -3
A = max(B,C)  = 4
```

ดังนั้น MAX ที่ A เลือกทาง B ได้ minimax value = 4 ไม่ใช่เลือกใบที่มีเลข 7 ทันที เพราะ MIN อาจบังคับให้ไปทางอื่น

เวลา O(b^m); พื้นที่แบบ DFS O(bm) เมื่อสร้างลูกขณะค้นหา หากเก็บต้นไม้ทั้งหมดจะใช้พื้นที่มากกว่านี้ การเลือกดีที่สุดอิงความแม่นของ evaluation หากตัดค้นที่ความลึกจำกัด

### Alpha-beta pruning

ตัดกิ่งที่ไม่อาจเปลี่ยน minimax value ที่ root โดยได้ค่า root เหมือน minimax ปกติ อาจเลือกทางต่างกันได้หากมีหลายทางคะแนนเท่ากัน

- เริ่ม `α = -∞`, `β = +∞`
- α คือขอบเขตล่างที่ MAX ทำได้แล้วตามเส้นทางที่พิจารณา
- β คือขอบเขตบนที่ MIN ทำได้แล้วตามเส้นทางที่พิจารณา
- ที่ MAX ปรับ `α = max(α, value)`
- ที่ MIN ปรับ `β = min(β, value)`
- **ตัดลูกที่ยังไม่สำรวจเมื่อ α ≥ β**

ตัวอย่างฝึกเพิ่ม: root เป็น MAX ตรวจลูกซ้ายซึ่งเป็น MIN แล้วได้ 3 จึงมี α=3 เมื่อตรวจลูกขวาซึ่งเป็น MIN พบใบแรกค่า 1 ทำให้ β=1 และ α≥β จึงตัดใบที่เหลือของลูกขวาได้ เพราะ MIN จะได้ไม่เกิน 1 ซึ่ง MAX ไม่เลือกแทน 3

กรณีเรียงลูกดีมาก เวลาอาจลดเหลือ O(b^(m/2)); กรณีแย่ยัง O(b^m) จึงไม่ได้ลดเลขชี้กำลังครึ่งหนึ่งทุกครั้ง

**จุดแก้ความสับสนในสไลด์หน้า 21:** E รับ β=3 แล้วพบลูกค่า 5 จะได้ α=5 และยังมี β=3 จึงตัดกิ่งได้ ข้อความที่เขียน β=5 เป็นการพิมพ์คลาดเคลื่อน นอกจากนี้ค่าที่คืนจากโหนดระหว่างตัดกิ่งอาจเป็น bound ไม่ใช่ค่าที่ประเมินครบทุกใบ

## 5. Knowledge Representation และ Logic

อ้างอิง: M5 หน้า 2–33 และตัวอย่างพิสูจน์หน้า 34–54

### พื้นฐานและการอนุมาน

**Data → Information → Knowledge:** ข้อเท็จจริงดิบ → ข้อมูลที่ประมวลผล → ความรู้ที่นำไปแก้ปัญหา

**Knowledge base (KB)** เก็บข้อเท็จจริงและกฎ ส่วน **inference mechanism** ใช้ข้อเท็จจริง/กฎเพื่อหาข้อสรุป

| การอนุมาน | รูปแบบ | ความแน่นอน |
|---|---|---|
| Deduction | P→Q และ P จึงได้ Q | ถูกต้องเมื่อ premises จริงและใช้กฎถูก |
| Induction | เห็นตัวอย่างหลายกรณีแล้วสรุปเป็นกฎทั่วไป | ไม่รับประกันทุกกรณี |
| Abduction | เห็น Q และรู้ P→Q จึงเสนอ P เป็นคำอธิบาย | เป็นสมมติฐาน; อาจมีสาเหตุอื่น |

### Propositional logic

ใช้สัญลักษณ์แทนประโยคที่เป็นจริงหรือเท็จ เช่น P = ฝนตก, Q = ถนนเปียก

| สัญลักษณ์ | ความหมาย |
|---|---|
| ¬P | ไม่ P |
| P ∧ Q | P และ Q |
| P ∨ Q | P หรือ Q แบบอย่างน้อยหนึ่งจริง |
| P → Q | ถ้า P แล้ว Q |
| P ↔ Q | P ก็ต่อเมื่อ Q |

| P | Q | P∧Q | P∨Q | P→Q | P↔Q |
|---|---|---|---|---|---|
| T | T | T | T | T | T |
| T | F | F | T | F | F |
| F | T | F | T | T | F |
| F | F | F | F | T | T |

**จำ:** implication เป็นเท็จเฉพาะ “เหตุจริง แต่ผลเท็จ” และ P→Q ไม่เท่ากับ Q→P

กฎพื้นฐาน: Modus ponens ใช้ P→Q กับ P ได้ Q; And-elimination ใช้ P∧Q ได้ P; And-introduction ใช้ P และ Q ได้ P∧Q; Or-introduction ใช้ P ได้ P∨Q; Double negation ใช้ ¬¬P ได้ P

### First-Order Logic (FOL)

FOL พูดถึงวัตถุ คุณสมบัติ และความสัมพันธ์ได้ เช่น `Human(John)` และ `Loves(John, Mary)`

- Constant: วัตถุเฉพาะ เช่น John
- Variable: ตัวแปรแทนวัตถุ เช่น x
- Function: คืนวัตถุ เช่น father(John)
- Predicate: ประโยคบอกคุณสมบัติ/ความสัมพันธ์ซึ่งมีค่าจริงหรือเท็จ เช่น Human(John)
- **∀x:** สำหรับทุก x
- **∃x:** มี x อย่างน้อยหนึ่งตัว

ตัวอย่าง:

```text
คนทุกคนต้องตาย:       ∀x (Human(x) → Mortal(x))
นักศึกษาบางคนเก่ง:    ∃x (Student(x) ∧ Smart(x))
ไม่มีแมวตัวใดเป็นสุนัข: ∀x (Cat(x) → ¬Dog(x))
```

**กับดัก ∀/∃:** “นักศึกษาทุกคนเก่ง” ใช้ implication หากเขียน `∀x(Student(x) ∧ Smart(x))` จะกลายเป็นทุกวัตถุในโดเมนเป็นนักศึกษาและเก่ง ส่วน “นักศึกษาบางคนเก่ง” ต้องยืนยันทั้งการเป็นนักศึกษาและเก่งด้วย ∧

ลำดับ quantifier ต่างกัน ความหมายต่างกัน:

- `∀x∃y Loves(x,y)` = ทุกคนรักใครบางคน โดยคนที่ถูกรักอาจต่างกัน
- `∃y∀x Loves(x,y)` = มีคนหนึ่งที่ทุกคนรัก เป็นคนเดียวกันสำหรับทุก x

กฎปฏิเสธ: `¬∀x P(x) ≡ ∃x ¬P(x)` และ `¬∃x P(x) ≡ ∀x ¬P(x)`

### CNF: Conjunctive Normal Form

CNF คือ AND ของ clauses โดยแต่ละ clause เป็น OR ของ literals เช่น `(¬P ∨ Q) ∧ (R ∨ S)`; literal คือ atomic proposition/predicate หรือรูปปฏิเสธของมัน

ขั้นตอนตามสไลด์:

1. กำจัด ↔: `P↔Q` เป็น `(P→Q)∧(Q→P)`
2. กำจัด →: `P→Q` เป็น `¬P∨Q`
3. ดัน ¬ เข้าไป: ใช้ De Morgan, double negation และกฎปฏิเสธ quantifier
4. เปลี่ยนชื่อตัวแปรต่าง scope ไม่ให้ชนกัน (standardize)
5. เลื่อน quantifier ออกหน้าโดยรักษา scope และลำดับที่จำเป็น
6. กำจัด ∃ ด้วย Skolemization
7. ละ ∀ โดยถือว่าตัวแปรที่เหลือเป็น universal
8. แจกแจง OR ครอบ AND: `P∨(Q∧R)` เป็น `(P∨Q)∧(P∨R)`
9. แยก clauses ตาม ∧
10. เปลี่ยนชื่อตัวแปรระหว่าง clauses ให้แยกกัน

**Skolemization:** ถ้า ∃ ไม่ขึ้นกับ ∀ ใด ให้ใช้ค่าคงที่ใหม่; ถ้าขึ้นกับ ∀ ให้ใช้ฟังก์ชันใหม่ของตัวแปร universal ที่เกี่ยวข้อง

```text
∃x P(x)              → P(a)
∀x ∃y R(x,y)         → ∀x R(x,f(x))
∀x ∀z ∃y R(x,z,y)   → ∀x ∀z R(x,z,f(x,z))
```

Skolemization รักษาคุณสมบัติการมีแบบจำลอง (equisatisfiability) สำหรับใช้พิสูจน์ ไม่ควรเรียกว่าเทียบเท่าทางตรรกะในภาษาเดิมทุกประการ

ตัวอย่างฝึกเพิ่ม:

```text
∀x (Student(x) → (Smart(x) ∧ Diligent(x)))
= ∀x (¬Student(x) ∨ (Smart(x) ∧ Diligent(x)))
CNF clauses:
  ¬Student(x) ∨ Smart(x)
  ¬Student(y) ∨ Diligent(y)
```

### Unification

หาการแทนค่าตัวแปรที่ทำให้ predicates ตรงกัน เช่น `Knows(John,x)` กับ `Knows(John,Mary)` ใช้ `{x ↦ Mary}`; ใน notation สไลด์เขียน `{Mary/x}`

- `P(x,x)` กับ `P(A,A)` ทำได้ด้วย x=A
- `P(x,x)` กับ `P(A,B)` ทำไม่ได้ถ้า A กับ B เป็นคนละค่าคงที่
- `P(John)` และ `¬P(Mary)` ไม่ได้หักล้างกันเพียงเพราะชื่อ predicate เหมือนกัน

### Resolution refutation

**หลัก:** อยากพิสูจน์ Q ให้เพิ่ม ¬Q ใน KB แล้วหา contradiction

กฎ: จาก `(A∨B)` และ `(¬B∨C)` อนุมานได้ `(A∨C)` โดย literals ที่หักล้างต้องตรงกันหลัง unification

ตัวอย่างฝึกเพิ่ม พิสูจน์ Mortal(Socrates):

```text
1. Human(Socrates)
2. ¬Human(x) ∨ Mortal(x)
3. ¬Mortal(Socrates)          [ปฏิเสธสิ่งที่จะพิสูจน์]
4. Mortal(Socrates)           [resolve 1,2 ด้วย x=Socrates]
5. □                         [resolve 3,4 ได้ empty clause]
```

ได้ empty clause จึงพิสูจน์ว่า KB อนุมาน Q ได้ หากยังหา empty clause ไม่พบ **ยังสรุปทันทีว่า Q เท็จไม่ได้** โดยเฉพาะ FOL ซึ่งกระบวนการอาจไม่สิ้นสุด

ตัวอย่างในสไลด์ที่ควรย้อนทำ: สมชายมีความสุข, Marcus ไม่ยังมีชีวิต, Marcus เกลียด Caesar และ John มีชีวิตน่าตื่นเต้น ทุกตัวอย่างใช้วิธีเดียวกันคือแปลง CNF → เพิ่มปฏิเสธเป้าหมาย → unify → resolve

## 6. Linear Regression และ Correlation

อ้างอิง: F1 หน้า 2–13

### อ่าน scatter plot และ r

Regression ทำนายค่าตัวเลข ส่วน correlation วัดทิศทางและความแน่นของความสัมพันธ์เชิงเส้น

- r อยู่ในช่วง −1 ถึง +1 หากความแปรปรวนของตัวแปรไม่เป็นศูนย์
- r>0: x มากขึ้น y มีแนวโน้มมากขึ้น
- r<0: x มากขึ้น y มีแนวโน้มน้อยลง
- |r| ใกล้ 1: ความสัมพันธ์เชิงเส้นแน่น
- r ใกล้ 0: ความสัมพันธ์เชิงเส้นอ่อน แต่อาจมีรูปแบบโค้งชัดได้
- ความสัมพันธ์จากข้อมูลอย่างเดียวไม่พิสูจน์เหตุและผล

สูตร Pearson correlation:

```text
r = Σ[(xᵢ−x̄)(yᵢ−ȳ)] / √[Σ(xᵢ−x̄)² · Σ(yᵢ−ȳ)²]

  = [nΣxy − (Σx)(Σy)]
    / √{[nΣx² − (Σx)²][nΣy² − (Σy)²]}
```

### สมการเส้นตรงและ Least Squares

**ŷ = b₀ + b₁x**

- x = ตัวแปรอิสระ/input; y = ค่าจริง; ŷ = ค่าทำนาย
- b₀ = intercept หรือค่าทำนายเมื่อ x=0
- b₁ = slope: เมื่อ x เพิ่ม 1 หน่วย ค่าทำนาย y เปลี่ยน b₁ หน่วย
- residual `eᵢ = yᵢ−ŷᵢ`
- Least squares เลือก b₀,b₁ ให้ `SSE = Σ(yᵢ−ŷᵢ)²` ต่ำที่สุด

```text
b₁ = Σ[(xᵢ−x̄)(yᵢ−ȳ)] / Σ(xᵢ−x̄)²
   = [nΣxy − (Σx)(Σy)] / [nΣx² − (Σx)²]
b₀ = ȳ − b₁x̄
```

### ตัวอย่างจากตารางต้นไม้ในสไลด์

ข้อมูลสรุป: n=8, Σx=73, Σy=321, Σxy=3142, Σx²=713, Σy²=14111

```text
x̄ = 73/8 = 9.125; ȳ = 321/8 = 40.125
b₁ = (8×3142 − 73×321)/(8×713 − 73²)
   = 1703/375 ≈ 4.5413
b₀ = 40.125 − 4.541333…×9.125 ≈ −1.3147
ŷ  ≈ −1.3147 + 4.5413x
r  = 1703/√(375×9847) ≈ 0.8862
```

แปลว่าเส้นผ่านศูนย์กลางลำต้นกับความสูงมีความสัมพันธ์เชิงเส้นบวกค่อนข้างสูง หาก x=10 จะทำนาย y≈44.10 (การหาสมการและแทน x นี้คำนวณต่อจากข้อมูลสไลด์เพื่อฝึก)

**วิธีทำข้อสอบ:** ทำตาราง x,y,x²,y²,xy → รวมแต่ละคอลัมน์ → หา x̄,ȳ → แทน b₁,b₀,r → ทำนาย → อธิบายหน่วยและทิศทาง เก็บทศนิยมไว้จนขั้นสุดท้าย

## 7. Classification: KNN และ Naive Bayes

อ้างอิง: F2 หน้า 2–8

### Classification คืออะไร

ทำนายกลุ่ม/คลาสที่มีอยู่จากข้อมูลมี label เช่น ประเภทดอกไม้หรือชนิดยา ต่างจาก regression ที่ทำนายจำนวน และต่างจาก clustering ที่ค้นหากลุ่มจากข้อมูลไม่มี label

### K-Nearest Neighbors (KNN)

**หลักจำ:** จุดใหม่อยู่ใกล้ข้อมูลคลาสใดมาก ก็ให้คลาสนั้นผ่านการโหวตของเพื่อนบ้าน k ตัว

1. เลือก k
2. คำนวณระยะจากจุดใหม่ไปข้อมูลฝึก
3. เรียงระยะและเลือก k จุดใกล้สุด
4. โหวตคลาสที่พบมากสุด

Euclidean distance: `d(x,z) = √Σⱼ(xⱼ−zⱼ)²`

ตัวอย่างฝึกเพิ่ม: จุดใหม่ (2,2); A=(1,1),คลาสแดง; B=(2,3),คลาสแดง; C=(5,5),คลาสน้ำเงิน

ระยะ = √2, 1, √18 ตามลำดับ; k=3 มีแดง 2 เสียง น้ำเงิน 1 เสียง → ทำนายแดง

**ข้อควรระวังเสริม:** k เล็กไวต่อ noise; k ใหญ่ทำให้ขอบเขตเรียบขึ้นแต่อาจกลบกลุ่มย่อย; features ที่หน่วยต่างกันควรปรับ scale เพราะระยะอาจถูกครอบงำด้วยตัวเลขใหญ่ เลือก k คี่ช่วยลดการเสมอสำหรับสองคลาส แต่ไม่ได้แก้การเสมอทุกกรณี

### Naive Bayes (NB)

Bayes’ theorem:

```text
P(C|X) = P(X|C)P(C) / P(X)
```

| พจน์ | ความหมาย |
|---|---|
| P(C) | Prior: โอกาสคลาสก่อนเห็น X |
| P(X|C) | Likelihood: โอกาสเห็นข้อมูลแบบนี้เมื่อกำหนดคลาส |
| P(C|X) | Posterior: โอกาสคลาสหลังเห็นข้อมูล |
| P(X) | Evidence: ตัวปรับให้เป็นความน่าจะเป็น |

สมมติฐาน naive คือ **features เป็นอิสระต่อกันเมื่อกำหนดคลาสแล้ว** จึงได้:

```text
P(X|C) = ∏ⱼ P(xⱼ|C)
ทำนายด้วย argmax_C [P(C) ∏ⱼ P(xⱼ|C)]
```

เปรียบเทียบคะแนนได้โดยไม่หาร P(X) เพราะเป็นตัวเดียวกันทุกคลาส คะแนนที่ยังไม่ normalize ไม่ใช่ posterior ที่รวมกันได้ 1

### ตัวอย่าง July จากสไลด์

ต้องจำแนก `Blonde, Average, Heavy, No lotion`; ตารางมีคลาส + จำนวน 3 คน และคลาส − จำนวน 5 คน

```text
score(+) = (3/8)×(2/3)×(2/3)×(1/3)×(3/3) = 1/18 ≈ 0.05556
score(−) = (5/8)×(2/5)×(1/5)×(2/5)×(2/5) = 1/125 = 0.008
```

ดังนั้นทำนาย **+** หากต้องการ posterior ภายใต้โมเดลนี้ให้ normalize:

`P(+|X) = (1/18)/[(1/18)+(1/125)] = 125/143 ≈ 0.8741`

**กับดัก:** likelihood ต้องนับ “ภายในคลาสนั้น” เช่น P(Blonde|+) หารด้วยจำนวนคนคลาส + ไม่ใช่หารด้วยจำนวนข้อมูลทั้งหมด

### อ่านโค้ดในสไลด์ให้ออก

`train_test_split` แบ่งข้อมูลฝึก/ทดสอบ; `test_size=0.3` กัน 30% ไว้ทดสอบ; `random_state=42` ทำให้การสุ่มแบ่งซ้ำได้; `KNeighborsClassifier(n_neighbors=3)` ใช้ KNN k=3; `GaussianNB()` คือ NB ที่จำลอง feature แบบต่อเนื่องด้วย Gaussian; `.fit(X_train,y_train)` ฝึก/เตรียมโมเดล; `.predict(X_test)` ทำนาย; `accuracy_score(y_test,y_pred)` วัดสัดส่วนที่ทายถูก

**เสริมเพื่อแยกโจทย์:** ตัวอย่าง July ใช้นับค่าหมวดหมู่ ขณะที่โค้ด Iris ใช้ GaussianNB จึงไม่ได้ประมาณ likelihood ด้วยการนับหมวดหมู่แบบเดียวกันทั้งหมด

## 8. Decision Tree และ ID3

อ้างอิง: F3 หน้า 3–17

ต้นไม้ใช้คำถามเกี่ยวกับ attributes แยกข้อมูลจนถึงคลาส:

- Root = คำถามแรก
- Internal/test node = attribute ที่ใช้ทดสอบ
- Branch = ค่าหรือผลการทดสอบ
- Leaf = คลาส/ผลลัพธ์

**ID3:** ที่แต่ละโหนดคำนวณ information gain ของ attributes ที่ใช้ได้ เลือกมากที่สุด แบ่งข้อมูล แล้วทำซ้ำกับแต่ละกลุ่ม; หยุดเมื่อเป็นคลาสเดียวกัน หรือเข้าเงื่อนไขหยุดที่กำหนด ถ้าไม่มี attribute เหลือแต่คลาสยังปนกัน วิธีพื้นฐานคือใช้คลาสเสียงข้างมาก

### Entropy และ Gain

```text
H(S) = −Σ_c p(c) log₂ p(c)
Gain(S,A) = H(S) − Σ_v [|S_v|/|S|] H(S_v)
```

- Entropy วัดความปนของคลาส
- ถ้าคลาสเดียว H=0; สำหรับ 2 คลาสที่สัดส่วนครึ่งต่อครึ่ง H=1
- กำหนดพจน์ 0log₂0 เป็น 0
- Gain คือ entropy ที่ลดลงหลังแบ่ง โดยต้องถ่วงตามขนาดกลุ่ม
- เลือก **gain มากสุด** ซึ่งเท่ากับเลือก entropy หลังแบ่งแบบถ่วงน้ำหนักต่ำสุด ณ โหนดนั้น

### ตัวอย่างผิวไหม้ในสไลด์

ข้อมูล 8 คน: ผิวไหม้ 3 ไม่ไหม้ 5

```text
H(S) = −(3/8)log₂(3/8) − (5/8)log₂(5/8) ≈ 0.9544
HairColor: Blonde มี 4 คน (2+,2−), Red มี 1 คน (+), Brown มี 3 คน (−)
H หลังแบ่ง = (4/8)×1 + (1/8)×0 + (3/8)×0 = 0.5
Gain(HairColor) ≈ 0.9544−0.5 = 0.4544
```

สไลด์ให้ HairColor≈0.45, Height≈0.26, Weight≈0.01, Lotion≈0.34 จึงใช้ HairColor เป็น root เมื่อแบ่งกลุ่ม Blonde ต่อ จะได้ Gain(Lotion)=1.0 สูงที่สุด จึงใช้ Lotion

### แปลงเป็นกฎ

ทุกเส้นทาง root→leaf เป็นกฎหนึ่งข้อ เชื่อมเงื่อนไขด้วย AND:

1. IF Hair=Blonde AND Lotion=Yes THEN ไม่ผิวไหม้
2. IF Hair=Blonde AND Lotion=No THEN ผิวไหม้
3. IF Hair=Red THEN ผิวไหม้
4. IF Hair=Brown THEN ไม่ผิวไหม้

**Occam’s razor:** ชอบโมเดลที่เรียบง่ายและสอดคล้องกับข้อมูล แต่ ID3 เป็นวิธีเลือกแบบ greedy จึงไม่รับประกันว่าจะพบต้นไม้เล็กที่สุดทั่วโลก

## 9. Clustering

อ้างอิง: F4 หน้า 2–3, 8–10, 13–29 และ 31–46

Clustering เป็น unsupervised learning: ข้อมูลไม่มี class label ต้องการให้ **ภายในกลุ่มคล้ายกันมาก** และ **ระหว่างกลุ่มคล้ายกันน้อย** เช่น แบ่งลูกค้า รูปภาพ หรือยีนตามรูปแบบข้อมูล

### ระยะทางและความคล้าย

Euclidean วัดความห่างของค่าพิกัด ส่วน correlation พิจารณาทิศทาง/รูปแบบการเปลี่ยนร่วมกัน สไลด์ยกตัวอย่างระดับการแสดงออกของยีนที่มีรูปแบบขึ้นลงคล้ายกัน

Metric distance มี d≥0, d(x,y)=0 ก็ต่อเมื่อ x=y, สมมาตร และ triangle inequality: `d(x,z)≤d(x,y)+d(y,z)` ไม่ใช่ similarity ทุกชนิดจะเป็น metric โดยอัตโนมัติ

### Hierarchical clustering

- **Agglomerative/bottom-up:** เริ่มหนึ่งข้อมูลต่อหนึ่งคลัสเตอร์ → รวมคู่ที่ใกล้สุด → ปรับระยะคลัสเตอร์ → ทำซ้ำ
- **Divisive/top-down:** เริ่มกลุ่มใหญ่แล้วแยกลงมา
- แสดงเป็น **dendrogram**; ความสูงที่รวมกันแสดงระยะตามเกณฑ์ linkage
- ตัด dendrogram ที่ระดับหนึ่งเพื่อเลือกจำนวนกลุ่ม ไม่จำเป็นต้องระบุ K ตั้งแต่เริ่ม

| Linkage | สูตรระยะระหว่าง A,B | ผลที่ควรจำ |
|---|---|---|
| Single | min d(a,b) | คู่ใกล้สุด; อาจเชื่อมเป็นสายยาว |
| Complete | max d(a,b) | คู่ไกลสุด; ชอบกลุ่มกระชับ |
| Average | Σ d(a,b)/(|A||B|) | เฉลี่ยทุกคู่ข้ามกลุ่ม |

ตัวอย่างฝึกเพิ่ม: A={1,2}, B={5,8} บนเส้นจำนวน ระยะข้ามกลุ่มคือ 4,7,3,6 ดังนั้น single=3, complete=7, average=5

ข้อจำกัด: ระยะ/วิธี linkage เปลี่ยนผลได้ การรวมแบบ greedy ย้อนกลับไม่ได้ในอัลกอริทึมพื้นฐาน และงานขนาดใหญ่มีต้นทุนสูง สไลด์ระบุอย่างน้อยระดับ O(n²) โดยวิธีทำจริงอาจสูงกว่า

### K-means

ต้องกำหนด K ล่วงหน้าแล้วแบ่งข้อมูลเป็น K กลุ่ม แต่ละข้อมูลอยู่กลุ่มเดียว

1. เลือก K และ initial centroids
2. **Assignment:** นำแต่ละจุดไปคลัสเตอร์ที่ centroid ใกล้สุด
3. **Update:** centroid ใหม่ = ค่าเฉลี่ยพิกัดของสมาชิกในคลัสเตอร์
4. ทำซ้ำจนสมาชิกไม่เปลี่ยนหรือเข้าเกณฑ์หยุด

Objective: `J = Σₖ Σ_{xᵢ∈Cₖ} ||xᵢ−μₖ||²` ต้องการให้ต่ำ

ตัวอย่างฝึกเพิ่ม: ข้อมูล 1,2,8,9; K=2; centroid เริ่ม 1 และ 8

- Assignment: C₁={1,2}; C₂={8,9}
- Update: μ₁=1.5; μ₂=8.5
- ทำซ้ำแล้วกลุ่มไม่เปลี่ยน หยุด
- J=(1−1.5)²+(2−1.5)²+(8−8.5)²+(9−8.5)²=1

### Elbow method และข้อจำกัด

พล็อต K กับ objective แล้วมองหาจุดที่การเพิ่ม K ช่วยลด objective ช้าลงมาก สไลด์ยก J ของ K=1,2,3 เป็น 873.0,173.1,133.6 จึงเห็นจุดศอกใกล้ K=2

K-means ไวต่อจุดเริ่มต้นและ outlier อาจหยุดที่ local optimum และทำงานได้เหมาะกับกลุ่มที่กระชับตามระยะที่เลือก การเพิ่ม K ทำให้ objective ที่ดีที่สุดไม่เพิ่มขึ้น ดังนั้นเลือก K จาก objective ต่ำอย่างเดียวไม่ได้

**แยกให้ขาด:** KNN: K=จำนวนเพื่อนบ้าน ใช้ label; K-means: K=จำนวนคลัสเตอร์ ไม่มี label

## 10. Artificial Neural Networks (ANN)

อ้างอิง: F5 หน้า 2–10 และ 11–25

### Neuron และโครงสร้าง

Neuron คำนวณสองส่วน: **รวม input แบบมีน้ำหนัก → ผ่าน activation function**

```text
z = b + Σᵢ wᵢxᵢ
o = φ(z)
```

Input layer รับข้อมูล; hidden layers สร้างตัวแทน/คุณลักษณะ; output layer ให้ผล; weight ควบคุมอิทธิพลการเชื่อม; bias เลื่อนจุดตัด/threshold โดยเขียนเป็น w₀x₀ และ x₀=1 ได้

Feedforward ส่งข้อมูลไปข้างหน้า ส่วน recurrent มีการใช้สถานะย้อนกลับ **Backpropagation เป็นวิธีคำนวณ gradient เพื่อฝึก** จึงไม่ใช่คำเดียวกับ recurrent architecture

### Perceptron

สไลด์หน้า 10 ใช้ผลแบบ bipolar: o=+1 เมื่อ z>0; o=−1 เมื่อ z≤0 อีกตัวอย่างตาราง AND ใช้ 0/1 จึงต้องตรวจ convention ก่อนทำโจทย์

Decision boundary คือ `b+Σwᵢxᵢ=0` เป็นเส้นตรงเมื่อมี 2 features หรือ hyperplane เมื่อมีหลาย features

Perceptron learning rule:

```text
error = t − o
Δwᵢ = η(t−o)xᵢ
wᵢ(new) = wᵢ(old) + Δwᵢ
b(new) = b(old) + η(t−o)
```

t=target, o=output, η=learning rate ถ้าทายถูก t−o=0 จึงไม่เปลี่ยนน้ำหนัก

ตัวอย่างฝึกเพิ่มแบบ 0/1: x=(1,1), w=(0.1,0.2), b=−0.5, t=1, η=0.1 ใช้ output=1 เมื่อ z>0

```text
z = 0.1+0.2−0.5 = −0.2 → o=0
error = 1
w ใหม่ = (0.2,0.3)
b ใหม่ = −0.4
```

**ข้อจำกัด:** single perceptron เรียนรู้ปัญหาที่ linearly separable เช่น AND, OR ได้ แต่ XOR แยกด้วยเส้นเดียวไม่ได้ จึงต้องใช้ multilayer network ที่มี nonlinear activations

### Activation functions

| ฟังก์ชัน | สูตร/ลักษณะ |
|---|---|
| Step/threshold | คืนคลาส 0/1 หรือ −1/+1 ตามเกณฑ์ |
| Sigmoid | σ(z)=1/(1+e^(−z)); ช่วง (0,1) |
| Sigmoid derivative | σ′(z)=σ(z)(1−σ(z)) |
| ReLU | max(0,z); ค่าติดลบเป็น 0 |

เพิ่มจำนวนชั้นโดยใช้แต่ linear functions ยังเทียบได้กับ linear function เดียว จึงต้องมี nonlinearity เพื่อสร้างขอบเขตที่ซับซ้อน

### Backpropagation

1. เริ่มน้ำหนักขนาดเล็ก
2. Forward pass หาค่า output ของทุก unit
3. คำนวณ loss ระหว่าง target กับ output
4. ส่ง error ย้อนผ่านชั้นต่าง ๆ โดย chain rule
5. ปรับน้ำหนักด้วย gradient descent แล้วทำซ้ำ

สูตรในสไลด์สำหรับ sigmoid และ squared error:

```text
E = ½ Σ_d Σ_k (t_kd − o_kd)²
δ_k = o_k(1−o_k)(t_k−o_k)                     [output unit]
δ_h = o_h(1−o_h) Σ_k w_kh δ_k                 [hidden unit]
Δw_ji = η δ_j x_ji
w_ji(new) = w_ji(old) + Δw_ji
```

ตรงนี้นิยาม δ ด้วย `(t−o)` จึงเขียน update เป็นบวก ซึ่งสอดคล้องกับ `w ← w−η∂E/∂w` อย่าสลับเครื่องหมายกับสูตรที่นิยาม δ อีกแบบ และควรคำนวณ deltas ด้วยชุดน้ำหนักเดิมก่อนปรับทั้งชุด

ตัวอย่างฝึกเพิ่ม: output sigmoid o=0.8, target t=1, input จากโหนดก่อนหน้า x=0.5, η=0.1

`δ=0.8×0.2×0.2=0.032`; `Δw=0.1×0.032×0.5=0.0016`

การฝึก neural network ไม่รับประกันว่าจะได้ global minimum จากการเริ่มต้นทุกครั้ง ตัวอย่างงาน ANN ในสไลด์ ได้แก่ prediction, classification, association, filtering และ conceptualization

## 11. Deep Learning: RNN, GAN, CNN

อ้างอิง: F6 หน้า 2–33

### เลือกสถาปัตยกรรมให้เหมาะงาน

| โมเดล | แนวคิด | งานตัวอย่าง |
|---|---|---|
| RNN | ใช้ hidden state ถ่ายทอดข้อมูลตามลำดับ | ข้อความ เสียง ข้อมูลตามเวลา |
| GAN | Generator สร้างข้อมูล แข่งขันกับ Discriminator | สร้าง/แปลงภาพตามตัวอย่างในสไลด์ |
| CNN | ใช้ filters เรียนรู้รูปแบบเชิงพื้นที่ | จำแนกภาพ ตรวจรูปแบบในภาพ |

RNN มีรูปแบบ one-to-many เช่น สร้างลำดับเพลง; many-to-one เช่น sentiment classification; many-to-many เช่น งานแปลภาษา ส่วน GAN มี G สร้างตัวอย่างจาก noise และ D พยายามแยกจริง/ปลอม โดยฝึกทั้งสองส่วนให้ดีขึ้นจากการแข่งขัน

### CNN: หน้าที่แต่ละชั้น

- **Convolution:** ใช้ filter/kernel ทาบบริเวณย่อย คูณแต่ละตำแหน่งแล้วบวก ได้ feature map
- **Stride:** จำนวนช่องที่เลื่อน filter ต่อครั้ง
- **Padding:** เติมขอบ เช่น 0 เพื่อควบคุมขนาด output
- **Pooling:** สรุปบริเวณย่อยเพื่อลดขนาด เช่น max pooling เลือกค่าสูงสุด
- **ReLU:** เปลี่ยนค่าลบเป็น 0 เพิ่ม nonlinearity
- **Flatten:** เรียงค่าของ feature maps เป็นเวกเตอร์
- **Fully connected:** นำ features มาคำนวณผลลัพธ์

ลำดับในตัวอย่างภาพกากบาทของสไลด์: **Input → Convolution → Pooling → ReLU → Flatten/Fully connected → Output** ภาพ CNN ทั่วไปอีกหน้าใช้ Conv→ReLU→Pooling ด้วย จึงควรอธิบายตามรูปที่โจทย์ให้ ไม่ถือว่ามีลำดับเดียวทุก architecture

### คำนวณ Convolution ตามสไลด์

Input 5×5 และ filter 3×3:

```text
Input:            Filter:
1 1 5 1 1         -1  1 -1
1 1 5 1 1          1  1  1
5 5 5 5 5         -1  1 -1
1 1 5 1 1
1 1 5 1 1
```

หน้าต่างซ้ายบนให้:

```text
(-1×1)+(1×1)+(-1×5)
+(1×1)+(1×1)+(1×5)
+(-1×5)+(1×5)+(-1×5) = −3
```

เมื่อทำครบทุกหน้าต่างโดยไม่ padding และ stride=1 จะได้ผลตามสไลด์หน้า 21:

```text
-3  5 -3
 5 21  5
-3  5 -3
```

ช่องกลางได้ 21 หากต้องทำข้อสอบ ให้เขียนการคูณทีละตำแหน่งและรวมโดยรักษาเครื่องหมายลบ แล้วค่อยเลื่อน filter ไปหน้าต่างถัดไป

### ขนาด output

สูตรเสริมสำหรับทำโจทย์ convolution ปกติที่ dilation=1 ใช้แยกแต่ละแกน:

```text
Output size = floor((N + 2P − F)/S) + 1
N=input size; P=padding ต่อด้าน; F=filter size; S=stride
```

- N=5,F=3,S=1,P=0 → 3×3
- N=5,F=3,S=1,P=1 → 5×5
- N=5,F=3,S=2,P=0 → 2×2
- อย่าลืมปัดลงและบวก 1; padding ไม่ได้ทำให้ขนาดเท่าเดิมเสมอ ต้องสัมพันธ์กับ F และ S

### Pooling, ReLU และ channels

Max pooling เลือกค่ามากสุดของแต่ละหน้าต่าง **ไม่ใช่คูณกับ filter** ตัวอย่างหน้าต่าง `[[2,−3],[10,5]]` ให้ 10; ReLU ของ `[-3,5,−1,0]` ให้ `[0,5,0,0]`

สไลด์ใช้ 3 output maps ขนาด 3×3 หลัง pooling จึง flatten ได้ **27 ค่า**

สำหรับภาพ RGB มี 3 input channels ในศัพท์มาตรฐาน **หนึ่ง filter แบบ 3D ครอบครบ 3 channels ให้หนึ่ง output channel** โดยคูณแต่ละ channel แล้วรวมกัน ถ้าต้องการ 3 output channels จะมี 3 filters แบบ 3D หรือมองเป็น kernels 2D จำนวน 3×3=9 ชุดตามภาพสไลด์ อย่าสับสนจำนวน kernel 2D กับจำนวน output maps
