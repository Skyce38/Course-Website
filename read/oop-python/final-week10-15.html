Week 10 — Linked List

Linked List เก็บข้อมูลเป็น Node ที่เชื่อมกันด้วย reference แต่ละ Node ไม่จำเป็นต้องอยู่ติดกันในหน่วยความจำ

คำศัพท์ ความหมาย
data ข้อมูลใน Node
next อ้างอิงไป Node ถัดไป
prev อ้างอิงไป Node ก่อนหน้า สำหรับ Doubly Linked List
head Node แรก
tail Node สุดท้าย
Traversal เดินผ่าน Node ทีละตัว

Singly Linked List เดินไปข้างหน้าผ่าน next ส่วน Doubly Linked List เดินได้สองทิศทางผ่าน next และ prev

Singly:  head → 10 → 20 → 30 → None

Doubly:  None ← 10 ⇄ 20 ⇄ 30 → None

การเดินอ่านข้อมูล

ใช้ตัวแปรชั่วคราว เพื่อให้ head ยังชี้จุดเริ่มต้นอยู่:

current = head
while current is not None:
    print(current.data)
    current = current.next

ก่อนเข้าถึง current.data หรือ current.next ต้องมั่นใจว่า current ไม่ใช่ None มิฉะนั้นอาจเกิด AttributeError

เปลี่ยนตัวแปร กับเปลี่ยนโครงสร้าง ต่างกัน

current = current.next       # เปลี่ยนว่า current ชี้ไปไหน
current.next = another_node  # เปลี่ยนการเชื่อมต่อของ Node

a = b ทำให้ทั้งสองตัวแปรอ้างอิง object เดียวกัน ไม่ได้สร้างสำเนา

แทรก Node หลังตำแหน่งที่รู้แล้ว

new_node.next = current.next
current.next = new_node

ต้องเก็บทางไป Node ถัดไปไว้ก่อน หากสลับสองบรรทัดนี้ new_node.next อาจชี้กลับมาหาตัวเอง และขาดทางไปส่วนท้ายเดิม

หาก current เป็น tail เดิม ต้องอัปเดต tail ให้เป็น Node ใหม่ด้วย

ตารางที่ควรจำ

สมมติ Linked List มีทั้ง head และ tail และใช้รูปแบบมาตรฐานที่เรียน

Operation Dynamic Array Singly LL Doubly LL
เข้าถึงตาม index O(1) O(n) O(n)
ค้นหาค่าแบบไล่ทีละตัว O(n) O(n) O(n)
เพิ่มด้านหน้า O(n) O(1) O(1)
เพิ่มด้านท้าย O(1) amortized O(1) O(1)
ลบด้านหน้า O(n) O(1) O(1)
ลบด้านท้าย O(1) O(n) O(1)
ลบ Node กลางที่มี reference อยู่แล้ว O(n) O(n) หากยังต้องหา Node ก่อนหน้า O(1)

กับดักข้อสอบ

  • Linked List ไม่ได้แทรกหรือลบเป็น O(1) ทุกกรณี: ถ้าต้องค้นหาตำแหน่งก่อน รวมแล้วอาจเป็น O(n)
  • Singly LL มี tail ก็ยังลบตัวท้ายเป็น O(n) เพราะต้องหา Node ก่อนหน้า
  • ถ้า Singly LL มี reference ของ Node ก่อนหน้าที่ต้องใช้พร้อมอยู่แล้ว การเชื่อมข้าม Node ทำได้ O(1)
  • เมื่อลบ Node สุดท้ายออก ต้องให้ head = tail = None
  • Doubly LL ใช้หน่วยความจำต่อ Node มากกว่า เพราะเก็บ prev เพิ่ม และต้องดูแลการเชื่อมทั้งสองทิศทาง

Week 11 — Stack

Stack = LIFO: Last In, First Out — เข้าหลัง ออกก่อน เหมือนกองจาน เพิ่มและนำออกจากด้าน top

Method หน้าที่
push(x) เพิ่มข้อมูลบนสุด
pop() นำข้อมูลบนสุดออกและคืนค่า
peek() ดูข้อมูลบนสุดโดยไม่เอาออก
is_empty() ตรวจว่าว่างหรือไม่

สำหรับ Stack ที่ใช้ Linked List และให้ top อยู่ที่ head ทั้งสี่ operation ทำได้ O(1)

ถ้าใช้ Python list ให้ใช้ด้านท้าย: append() สำหรับ push และ pop() สำหรับ pop โดยการเพิ่มท้ายมีต้นทุน O(1) แบบ amortized

Stack เป็น ADT (Abstract Data Type) ที่กำหนดพฤติกรรมและ operation ส่วน implementation อาจใช้ Array หรือ Linked List ก็ได้ การซ่อนโครงสร้างภายในหลัง interface เดียวกันเชื่อมกับหลัก encapsulation

ตัวอย่างไล่โค้ด

s = []
s.append(10)
s.append(20)
a = s.pop()
s.append(30)
print(a, s[-1])

ผลลัพธ์:

20 30

pop() เอา 20 ออก จากนั้น 30 กลายเป็นตัวบนสุด

Call Stack

  • เรียกฟังก์ชัน → เพิ่ม stack frame ของการเรียกนั้น
  • ฟังก์ชัน return → นำ frame ออก แล้วกลับไปทำงานต่อที่ผู้เรียก
  • ถ้า A เรียก B และ B เรียก C เมื่อ C จบ จะกลับไป B ก่อน
  • Recursion ต้องมีเงื่อนไขหยุด การเรียกซ้อนลึกเกินไปอาจเกิด RecursionError

ตรวจวงเล็บ

วงเล็บที่เปิดล่าสุดต้องปิดก่อน:

  1. พบวงเล็บเปิด → push
  2. พบวงเล็บปิด → Stack ต้องไม่ว่าง และต้องตรงชนิดกับตัวที่ pop
  3. อ่านจบ → Stack ต้องว่าง
ข้อความ ผล
([]{}) ถูก
([)] ผิด แม้จำนวนเปิดและปิดจะครบ
(() ผิด เพราะมีวงเล็บเปิดค้าง
)( ผิด เพราะพบวงเล็บปิดก่อน

ตรวจข้อความยาว n ตัว ใช้เวลา O(n) และพื้นที่เพิ่มได้สูงสุด O(n)

Undo/Redo

ใช้ Stack สองกอง:

การกระทำ สิ่งที่ต้องทำ
Action ใหม่ เก็บสถานะเดิมลง undo_stack, ล้าง redo_stack, เปลี่ยนสถานะ
Undo เก็บสถานะปัจจุบันลง redo_stack แล้วนำสถานะจาก undo_stack มาใช้
Redo เก็บสถานะปัจจุบันลง undo_stack แล้วนำสถานะจาก redo_stack มาใช้

จุดสำคัญ: เมื่อ Undo แล้วทำ action ใหม่ ต้อง ล้าง redo_stack เพราะเกิดเส้นทางใหม่แล้ว

Postfix — เชื่อมกับ Lab11-1

พบตัวเลขให้ push พบ operator ให้ pop ตัวถูกดำเนินการออกมาคำนวณ แล้ว push ผลกลับ

3 4 + 2 *  →  (3 + 4) × 2  →  14

right = stack.pop()
left = stack.pop()
result = left - right

ตัวที่ pop ก่อนเป็นตัวขวา ต้องระวังเป็นพิเศษกับ - และ /

ตัวอย่าง 8 2 - ต้องเป็น 8 - 2 = 6 ไม่ใช่ 2 - 8

Week 12 — Queue และรูปแบบต่าง ๆ

โครงสร้าง หลักการ ตัวอย่าง
Queue FIFO: เข้าก่อน ออกก่อน คิวรอรับบริการ
Circular Queue คิวที่ index วนกลับมาใช้ช่องเดิม Buffer ขนาดจำกัด
Deque เพิ่มและนำออกได้ทั้งสองด้าน ประวัติแบบจำกัดจำนวน
Priority Queue ความสำคัญสูงออกก่อน คิวผู้ป่วยตามความเร่งด่วน

Queue ธรรมดา

  • enqueue(x) เพิ่มที่ท้าย หรือ rear
  • dequeue() นำออกที่หน้า หรือ front
  • peek() ดูตัวหน้าโดยไม่เอาออก
  • Linked List Queue มี head และ tail เพื่อให้เพิ่มท้ายและนำออกหน้าเป็น O(1)
  • หากไม่มี tail การเพิ่มท้ายอาจต้อง traverse เป็น O(n)
  • นำสมาชิกตัวสุดท้ายออกแล้ว ต้องตั้งทั้ง head และ tail เป็น None

Circular Queue

ใช้ % capacity เพื่อวน index กลับมาต้นอาร์เรย์:

rear = (rear + 1) % capacity
front = (front + 1) % capacity

เช่น capacity = 5 ถ้า index = 4 เลื่อนอีกหนึ่งครั้งจะได้ 0

ใน implementation ตามสไลด์ rear หมายถึง ช่องที่จะเขียนข้อมูลถัดไป โดยเขียนก่อนแล้วจึงเลื่อน:

data[rear] = item
rear = (rear + 1) % capacity
size += 1

front == rear อาจเกิดได้ทั้งตอนว่างและตอนเต็ม จึงใช้ size แยกสถานะ:

size == 0         # ว่าง
size == capacity  # เต็ม

ถ้าต้องอ่านข้อมูลตามลำดับจากหน้าไปท้าย ตำแหน่งจริงของสมาชิกตัวที่ i คือ:

index = (front + i) % capacity

Deque ใน Python

from collections import deque

d = deque([10, 20])
d.append(30)      # เพิ่มขวา
d.appendleft(5)   # เพิ่มซ้าย
d.pop()          # เอาขวาออก ได้ 30
d.popleft()      # เอาซ้ายออก ได้ 5

การเพิ่มและนำออกที่ปลายทั้งสองด้านทำได้ O(1) จึงใช้เป็นทั้ง Stack และ Queue ได้ตามวิธีเรียกใช้

d = deque([1, 2, 3], maxlen=3)
d.append(4)
print(list(d))  # [2, 3, 4]

เมื่อเต็มแล้วเพิ่มด้านขวา ข้อมูลเก่าด้านซ้ายจะถูกทิ้ง

Priority Queue

ตามตัวอย่างที่ใช้ heapq แบบ min-heap: ค่าตัวเลข priority น้อยกว่า ออกก่อน

เก็บข้อมูลเป็น:

(priority, arrival_order, data)

Python เทียบ tuple จากซ้ายไปขวา:

  1. เทียบ priority
  2. ถ้าเท่ากัน เทียบลำดับมาถึง
  3. counter ที่ไม่ซ้ำกันช่วยไม่ให้ต้องเปรียบเทียบ data

ตัวอย่าง (1, 0, "A") ออกก่อน (1, 1, "B") และทั้งสองออกก่อน (2, 2, "C")

Operation ของ heap เวลา
เพิ่มข้อมูล O(log n)
นำตัวน้อยสุดออก O(log n)
ดูตัวน้อยสุดที่ heap[0] O(1)

กับดัก: Priority Queue ไม่ได้เป็น O(1) ทุก operation และการรักษา FIFO เมื่อ priority เท่ากันต้องออกแบบตัวตัดสิน เช่น arrival counter ไม่ใช่คุณสมบัติที่ heap ทำให้เองเสมอ

Week 13 — Big-O และ Sorting พื้นฐาน

Big-O

Big-O บอก อัตราการเติบโตของงานเมื่อจำนวนข้อมูลเพิ่มขึ้น ไม่ได้บอกจำนวนวินาทีโดยตรง

อัตราเติบโตจากน้อยไปมาก:
O(1) < O(log n) < O(n) < O(n log n) < O(n²)
  • ลูปครบ n ตัวหนึ่งรอบ → O(n)
  • ลูปซ้อน โดยแต่ละลูปวิ่ง n รอบ → O(n²)
  • ลดขนาดปัญหาเหลือครึ่งหนึ่งซ้ำ ๆ โดยทำงานคงที่ต่อขั้น → O(log n)
  • 3n² + 5n + 7 → O(n²)
  • Binary Search ต้องใช้ข้อมูลที่เรียงแล้ว และบน Array ใช้เวลา O(log n)

Sorting สามแบบต่างกันอย่างไร

Algorithm วิธีจำ สิ่งที่เกิดหลังจบหนึ่งรอบหลัก
Bubble Sort เทียบคู่ติดกันแล้วสลับ ถ้าวิ่งซ้ายไปขวา ค่ามากสุดของส่วนที่ยังไม่เรียงไปอยู่ท้าย
Selection Sort หาค่าน้อยสุดแล้วสลับมาไว้หน้า ได้ค่าน้อยสุดถัดไปในตำแหน่งที่ถูกต้อง
Insertion Sort หยิบตัวถัดไปมาเสียบในส่วนซ้าย ส่วนซ้ายที่เรียงแล้วขยายขึ้นหนึ่งตัว

ตัวอย่างจาก [5, 3, 8, 1, 2] เรียงน้อยไปมาก:

Algorithm หลังรอบแรก
Bubble วิ่งซ้ายไปขวาหนึ่ง pass [3, 5, 1, 2, 8]
Selection เลือก minimum รอบแรก [1, 3, 8, 5, 2]
Insertion จบ i = 1 [3, 5, 8, 1, 2]

ตารางที่ควรจำ

Algorithm Best Average Worst Stable
Bubble มี early termination O(n) O(n²) O(n²) ใช่ เมื่อสลับเฉพาะค่าที่มากกว่า
Selection แบบสลับ minimum O(n²) O(n²) O(n²) ไม่ใช่
Insertion O(n) O(n²) O(n²) ใช่ เมื่อเลื่อนเฉพาะค่าที่มากกว่า key

Stable หมายถึง เมื่อ key เท่ากัน ยังรักษาลำดับเดิมของรายการเหล่านั้น เช่น 3A มาก่อน 3B ก่อน sort ก็ยังมาก่อนหลัง sort

จุดหลอก

  • Bubble ได้ best O(n) เมื่อมีเงื่อนไข หยุดเมื่อทั้ง pass ไม่มีการ swap ถ้ายังวนครบทุก pass ตามลูปเดิม อาจยังเป็น O(n²)
  • Selection ยังต้องหา minimum จนครบ แม้ข้อมูลเรียงแล้ว
  • Selection เปรียบเทียบรวม n(n−1)/2 ครั้ง และ swap ไม่เกิน n−1 ครั้งในแบบมาตรฐาน
  • Insertion เหมาะกับข้อมูล ขนาดเล็กหรือเกือบเรียงแล้ว
  • Insertion ใช้ arr[j] > key เพื่อไม่เลื่อนสมาชิกที่ค่าเท่ากันข้ามกัน
  • เงื่อนไข j >= 0 and arr[j] > key ใช้ short-circuit: เมื่อเงื่อนไขแรกเป็น False จะไม่อ่านเงื่อนไขหลัง

ระวังการนับพื้นที่

แกนของสามอัลกอริทึมใช้พื้นที่เพิ่ม O(1) แต่ถ้าโค้ดเริ่มด้วย arr.copy() แบบตัวอย่างในสไลด์ การสร้างสำเนาจะใช้พื้นที่เพิ่ม O(n) ต้องดูว่าข้อสอบถามตัวอัลกอริทึมหรือโค้ดทั้งฟังก์ชัน

Week 14 — Merge Sort, Quick Sort และ Timsort

Divide and Conquer คือ แบ่งปัญหา → แก้ปัญหาย่อย → รวมผล

Recursion ต้องมี base case เช่น ข้อมูลเหลือ 0 หรือ 1 ตัวให้หยุด

Merge Sort

  1. แบ่งข้อมูลเป็นสองครึ่ง
  2. เรียงแต่ละครึ่งด้วย recursion
  3. merge สองฝั่งที่เรียงแล้ว
[4, 1, 3, 2]
      ↓ แบ่ง
[4, 1]       [3, 2]
      ↓ เรียงแต่ละฝั่ง
[1, 4]       [2, 3]
      ↓ merge
[1, 2, 3, 4]
  • เวลา O(n log n) ทั้ง best, average และ worst สำหรับแบบมาตรฐานที่เรียน
  • พื้นที่เพิ่ม O(n)
  • เป็น stable เมื่อค่าซ้ายและขวาเท่ากันแล้ว เลือกฝั่งซ้ายก่อน เช่นใช้ left[i] <= right[j]
  • merge สองลิสต์ที่เรียงแล้ว รวมความยาว n ใช้เวลา O(n)

ที่มาของ O(n log n): มีระดับการแบ่งประมาณ log₂n และมีงานรวม O(n) ต่อระดับ

ตัวอย่าง n = 8 แบ่งจนเหลือหนึ่งตัวได้ 3 ครั้ง ถ้านับระดับรากเป็น level 0 จะมีทั้งหมด 4 level รวมราก ต้องอ่านว่าข้อสอบนับอย่างไร

Quick Sort

  1. เลือก pivot
  2. partition ข้อมูลรอบ pivot
  3. เรียงฝั่งซ้ายและขวาต่อด้วย recursion

ใน Lomuto partition ตามสไลด์ ใช้ตัวท้ายเป็น pivot เมื่อ partition จบ pivot จะอยู่ในตำแหน่งที่ถูกต้อง แต่ ข้อมูลแต่ละฝั่งอาจยังไม่เรียง

Algorithm Best Average Worst Stable
Merge Sort O(n log n) O(n log n) O(n log n) ใช่ เมื่อจัดการค่าเท่ากันถูกต้อง
Quick Sort แบบที่เรียน O(n log n) O(n log n) O(n²) ไม่ใช่

จุดหลอกของ Quick Sort

  • เลือกตัวท้ายเป็น pivot เจอข้อมูลเรียงแล้ว → แบ่งไม่สมดุล → worst O(n²)
  • Random pivot หรือ median-of-three ช่วยลดปัญหาการเลือก pivot แต่ไม่ได้รับประกันว่าไม่มี worst case
  • Median-of-three เลือกค่ากลางจากค่าที่ตำแหน่งต้น กลาง ท้าย ไม่ใช่ median ของข้อมูลทั้งหมด
  • Call stack ใช้ O(log n) เมื่อแบ่งสมดุล และอาจถึง O(n) เมื่อแบ่งแย่มาก
  • ถ้าโค้ดสร้างสำเนา list ก่อนเริ่ม ต้องนับพื้นที่ของสำเนาเพิ่มด้วย

Python sorting

ตามบทเรียน Python ใช้แนวคิด Timsort ซึ่งผสมการจัดการข้อมูลช่วงเล็กแบบ Insertion Sort กับการ merge และเป็น stable sort

a = [3, 1, 2]
b = sorted(a)  # สร้าง list ใหม่
# a = [3, 1, 2], b = [1, 2, 3]

# a = [1, 2, 3], result = None

จำให้แม่น: sorted(a) คืน list ใหม่ ส่วน a.sort() คืน None

Week 15 — Hash Table

Hash Table ใช้ key คำนวณว่าจะไปเก็บหรือค้นหาที่ bucket ใด:

index = hash(key) % capacity

เมื่อ capacity เป็นจำนวนเต็มบวก ผล index อยู่ในช่วง 0 ถึง capacity−1

Hash function ที่ดีควรให้ผลคงที่สำหรับ key เดิมภายใต้บริบทการทำงานเดียวกัน กระจาย key ได้ดี และคำนวณรวดเร็ว

Collision

Collision คือ key ต่างกัน แต่ได้ bucket index เดียวกัน ไม่ได้หมายความว่า key เหมือนกัน

วิธีจัดการ collision หลักการ
Chaining bucket หนึ่งเก็บหลาย (key, value)
Linear Probing ถ้าช่องชน ให้หาช่องถัดไป และวนด้วย modulo

Tombstone สำคัญอย่างไร

สมมติ A กับ B มี index เริ่มต้นเดียวกัน:

index 2: A
index 3: B  ← ชนจึงเลื่อนไปช่องถัดไป

หากลบ A แล้วใส่ None การค้นหา B ที่เริ่มจาก index 2 อาจหยุดทันทีและเข้าใจว่าไม่พบ B

จึงใช้ Tombstone แทน:

  • None → ช่องว่างที่ใช้เป็นจุดหยุดค้นหา
  • Tombstone → เคยมีข้อมูลแล้วถูกลบ ต้องค้นต่อ

Load factor และ Rehashing

load_factor = size / capacity

เช่น size = 6, capacity = 8 → load factor = 0.75

Rehashing คือสร้างตารางขนาดใหม่ แล้วคำนวณ bucket ของข้อมูลเดิมใหม่ เพราะ % capacity เปลี่ยนไป

  • ค้นหา/เพิ่ม/ลบ: โดยเฉลี่ย O(1) เมื่อกระจาย hash ดีและควบคุม load factor
  • กรณีแย่สุด: O(n)
  • Rehash หนึ่งครั้ง: โดยทั่วไป O(n) ภายใต้เงื่อนไขการกระจาย hash ที่ดี
  • การเพิ่มต่อเนื่องยังได้ต้นทุนเฉลี่ยแบบ amortized O(1) ภายใต้เงื่อนไขดังกล่าว
  • เกณฑ์ขยายตารางขึ้นอยู่กับ implementation ไม่ใช่กฎตายตัวของ Hash Table ทุกแบบ

จุดออกข้อสอบเฉพาะโค้ดในสไลด์: ตรวจ load_factor >= 0.75 ก่อน insert ดังนั้นการเพิ่มจนแตะ 0.75 พอดี จะยังไม่ rehash จนกว่าจะเรียก insert ครั้งถัดไป

Python ที่ควรจำ

  • dict วนตามลำดับการเพิ่ม key ไม่ได้เรียง key ให้อัตโนมัติ
  • ใส่ key เดิมอีกครั้ง → อัปเดต value จำนวน key ไม่เพิ่ม
  • key ต้อง hashable เช่น int, str, tuple ที่สมาชิกทั้งหมด hashable
  • list ใช้เป็น dict key ไม่ได้ และ tuple ที่มี list เป็นสมาชิกก็ใช้เป็น key ไม่ได้
  • hash() ของ string อาจต่างกันเมื่อเปิด interpreter คนละครั้ง แต่คงที่สำหรับ string เดิมภายในรอบการทำงานเดียวกัน
  • is ตรวจว่าเป็น object เดียวกัน ส่วน == ตรวจความเท่ากันของค่า
  • ตัวอย่างคลาส HashTable ในสไลด์โยน KeyError เมื่อค้นหาหรือลบ key ที่ไม่มีอยู่

ระวัง reference ซ้ำตอนสร้าง buckets

wrong = [[]] * 3
wrong[0].append(1)
print(wrong)  # [[1], [1], [1]]

ทั้งสามช่องอ้างอิง list ตัวเดียวกัน ต้องสร้างแยก:

correct = [[] for _ in range(3)]
correct[0].append(1)
print(correct)  # [[1], [], []]

รายการทบทวนก่อนสอบ

  • แยก LIFO / FIFO / priority และไล่ลำดับข้อมูลออกได้
  • อธิบายว่า Linked List operation ใดต้องค้นหาก่อน และข้อใดเปลี่ยน reference ได้ทันที
  • จำกรณี List/Queue ว่าง และกรณีเหลือสมาชิกตัวเดียว
  • ตรวจวงเล็บ และอธิบายการล้าง redo_stack หลัง action ใหม่ได้
  • คำนวณ Postfix โดยไม่สลับ operand ของการลบและหาร
  • คำนวณการวน index ของ Circular Queue และแยกสถานะเต็ม/ว่างด้วย size
  • อ่าน tuple (priority, counter, data) และเรียงลำดับนำออกได้
  • ไล่ Bubble, Selection, Insertion ให้ได้อย่างน้อยสองรอบ
  • จำเวลา Sorting พร้อมเงื่อนไข best/worst และความหมายของ stable
  • อธิบาย Merge Sort ว่าทำไมเป็น O(n log n)
  • อธิบาย pivot และกรณีแย่สุดของ Quick Sort
  • แยก sorted(a) กับ a.sort() ได้
  • คำนวณ modulo และ load factor
  • อธิบาย collision → probing → tombstone → rehash ได้
  • อ่าน reference ซ้ำจาก [[]] * n ได้
  • เวลาเจอ Big-O อ่านก่อนว่ารวมการค้นหา การ copy และ call stack หรือไม่

ถ้ามีเวลาน้อย ให้ทบทวนตามลำดับนี้

  1. ตาราง Big-O ของ Linked List และ Sorting
  2. ไล่ลำดับ Stack, Queue, Priority Queue
  3. ไล่ Sorting ทีละ pass
  4. Circular Queue, load factor และ modulo
  5. จุดหลอก: stable, tombstone, sort() คืน None, การอ้างอิง object เดียวกัน
