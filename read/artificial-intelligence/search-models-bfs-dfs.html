Frontier และชุดสถานะที่เคยพบ

คำอธิบาย implementation ต่อไปนี้เขียนเพิ่ม สอดคล้องกับ LIFO/FIFO หน้า 16/23

  • BFS ใช้ queue: เข้าท้าย ออกหัว กำหนด parent ตอน enqueue เพื่อเป็นทั้ง discovered set และข้อมูลย้อนเส้นทาง จึงไม่ enqueue state เดิมซ้ำ
  • DFS ตัวอย่างนี้ใช้ stack ของ frame แต่ละ frame เก็บ state และ iterator ของเพื่อนบ้านที่ยังไม่ลอง เพิ่ม parent เมื่อเข้าสู่ frame ใหม่ และย้อนกลับ (backtrack) เมื่อ frame นั้นไม่มีทางใหม่
  • order ในโค้ดหมายถึง visit: BFS ตอน dequeue, DFS ตอนเข้า frame ไม่ใช่คำรับรองว่าทุกตัวถูก expanded แล้ว เป้าหมายถูกตรวจและหยุดก่อนสร้างลูก
  • การมีใน parent ไม่ได้แปลว่าประมวลผลเสร็จแล้ว และรายการ parent ที่พิมพ์ในตารางเรียงตามเวลาค้นพบ ไม่ใช่ลำดับตัวอักษร
  • ไม่มีการ mark complete อัตโนมัติจากการเปิด/อ่านโค้ด ปุ่มอ่านจบของเว็บไซต์เป็นสถานะการเรียนแยกต่างหาก

สำหรับปัญหามีต้นทุนต่างกัน การเจอ state ครั้งแรกไม่ได้แปลว่าเจอทางต้นทุนต่ำสุด การเก็บ visited แบบนี้ตั้งใจใช้กับ BFS/DFS ในบท ไม่ใช่อัลกอริทึมหาเส้นทางต้นทุนต่ำสุดทั่วไป

ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

  • ใช้ pop() ท้าย list แล้วเรียกว่า BFS: ต้องนำหัว queue ออก เช่น deque.popleft()
  • บอกว่า DFS ลองตัวอักษรน้อยก่อน แต่ push A แล้ว B ลง stack ธรรมดา: B จะถูก pop ก่อน ต้องกำหนดกลไกให้ตรง trace
  • เรียกทุก state ที่ discovered ว่า expanded: BFS อาจมี D ค้างอยู่ตอนคืน goal
  • ใช้ tree search กับกราฟวงจรโดยไม่ตรวจซ้ำ: frontier อาจโตไม่สิ้นสุด
  • DFS mark ทุก sibling ว่า visited ก่อนลงกิ่ง แล้วอ้างว่าเหมือน recursive DFS: อาจเปลี่ยน discovery tree เมื่อมีขอบเชื่อม sibling ใช้ frame ที่เก็บจุดกลับมาอย่างในตัวอย่าง
  • อ้าง BFS สั้นที่สุดด้านระยะทางบนแผนที่ที่ cost ต่างกัน หรืออ้าง DFS เจอคำตอบแรกจึงดีที่สุด
  • ใช้แค่พิกัดเป็น state ทั้งที่โจทย์มีกุญแจ/พลังงานซึ่งมีผลต่อการเดินต่อ ต้องรวมข้อมูลที่จำเป็นนั้นใน state ด้วย
  • นำความซับซ้อนของ tree frontier ไปอ้างเป็นหน่วยความจำรวมของ graph search ที่เก็บ visited และ trace

  • DFS ใช้ LIFO และ backtrack; ไม่รับประกันตื้นสุดหรือต้นทุนต่ำสุด
  • ระบุ successor order จุด mark discovered และจุดตรวจ goal ก่อนเขียน trace
  • กัน state ซ้ำเพื่อจัดการวงจร และระบุ finite/infinite, tree/graph และ trace overhead ก่อนอ้าง complexity
