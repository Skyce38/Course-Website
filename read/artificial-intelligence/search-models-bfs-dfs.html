เป้าหมายการเรียนรู้ (Learning Objectives)

  • กำหนดสถานะ การกระทำ ต้นทุน สถานะเริ่มต้น และเงื่อนไขเป้าหมายของปัญหาได้
  • แยกกราฟสถานะ (State Space Graph) ออกจากต้นไม้การค้นหา (Search Tree) ได้
  • ติดตาม Frontier และสถานะที่ค้นพบโดยไม่สับสนกับสถานะที่ขยายแล้ว
  • อธิบายและ trace DFS แบบ LIFO และ BFS แบบ FIFO ด้วยลำดับเพื่อนบ้านที่แน่นอนได้
  • วิเคราะห์ความครบถ้วน ความเหมาะที่สุด เวลา และหน่วยความจำภายใต้สมมติฐานที่ระบุ
  • แก้โจทย์กราฟและกริดจากหน้า 31–32 พร้อมตรวจเส้นทางและการป้องกันวงจรได้

อ่าน พื้นฐาน AI และตัวกระทำอัจฉริยะ ก่อน และทบทวน list, dictionary, set, stack และ queue ของ Python ตามจำเป็น ความรู้โครงสร้างข้อมูลนี้เป็น prerequisite ที่ผู้เขียนแนะนำ

เกมและปริศนาจากภาพ (Tic-Tac-Toe / 8-Puzzle)

หน้า 12 แสดงต้นไม้กระดาน Tic-Tac-Toe ที่แตกกิ่งจากการวางหมาก ส่วนหน้า 13 ถาม states/operators/goal/path cost ของ 8-Puzzle และหน้า 14 แสดงการย้ายช่องว่าง ตัวอย่างการกำหนดปัญหาต่อไปนี้เป็นคำตอบที่ผู้เขียนจัดทำเพิ่ม

  • Tic-Tac-Toe: state ต้องระบุกระดานและผู้เล่นที่จะเดิน การเดินคือลงช่องว่าง แต่การชนะเมื่อมีคู่แข่งต้องคิดการเลือกของอีกฝ่ายด้วย การพบเส้นทางที่ชนะในต้นไม้เพียงทางเดียวไม่รับประกันชนะทุกการตอบโต้
  • 8-Puzzle: state คือการจัดแผ่น 1–8 และช่องว่าง การกระทำคือเลื่อนช่องว่างขึ้น/ลง/ซ้าย/ขวาภายในขอบกระดาน Goal test เปรียบเทียบกับกระดานเป้าหมายที่กำหนด และในตัวอย่างนี้กำหนด cost = 1 ต่อการเลื่อน
  • หน้า 13 ใช้เป้าหมายแบบวนรอบ: แถวบน 1 2 3, แถวกลาง 8 _ 4, แถวล่าง 7 6 5 ไม่ควรแทนด้วยเป้าหมายแบบอื่นโดยไม่บอก หน้า 21/27 ใช้ trace คนละภาพ ไม่สมมติว่ามี successor order เดียวกับตัวอย่างที่เขียนใหม่ในบทนี้

Frontier และชุดสถานะที่เคยพบ

คำอธิบาย implementation ต่อไปนี้เขียนเพิ่ม สอดคล้องกับ LIFO/FIFO หน้า 16/23

  • BFS ใช้ queue: เข้าท้าย ออกหัว กำหนด parent ตอน enqueue เพื่อเป็นทั้ง discovered set และข้อมูลย้อนเส้นทาง จึงไม่ enqueue state เดิมซ้ำ
  • DFS ตัวอย่างนี้ใช้ stack ของ frame แต่ละ frame เก็บ state และ iterator ของเพื่อนบ้านที่ยังไม่ลอง เพิ่ม parent เมื่อเข้าสู่ frame ใหม่ และย้อนกลับ (backtrack) เมื่อ frame นั้นไม่มีทางใหม่
  • order ในโค้ดหมายถึง visit: BFS ตอน dequeue, DFS ตอนเข้า frame ไม่ใช่คำรับรองว่าทุกตัวถูก expanded แล้ว เป้าหมายถูกตรวจและหยุดก่อนสร้างลูก
  • การมีใน parent ไม่ได้แปลว่าประมวลผลเสร็จแล้ว และรายการ parent ที่พิมพ์ในตารางเรียงตามเวลาค้นพบ ไม่ใช่ลำดับตัวอักษร
  • ไม่มีการ mark complete อัตโนมัติจากการเปิด/อ่านโค้ด ปุ่มอ่านจบของเว็บไซต์เป็นสถานะการเรียนแยกต่างหาก

สำหรับปัญหามีต้นทุนต่างกัน การเจอ state ครั้งแรกไม่ได้แปลว่าเจอทางต้นทุนต่ำสุด การเก็บ visited แบบนี้ตั้งใจใช้กับ BFS/DFS ในบท ไม่ใช่อัลกอริทึมหาเส้นทางต้นทุนต่ำสุดทั่วไป

ค้นหาเชิงลึก (Depth-First Search: DFS)

หน้า 15–16: เลือกไปตามกิ่งลึกก่อน ใช้ LIFO stack หน้า 20 แสดงรูปแบบ recursive ที่ลอง successor และกลับมาลองตัวถัดไปเมื่อไม่สำเร็จ Python ด้านล่างใช้ frame stack เพื่อรักษาลำดับแบบ recursive โดยไม่อาศัย call stack ของ Python

หาก A มีลูก C แล้ว D ต้องสำรวจ C จนหมดก่อนลอง D ไม่ใช่แค่ใส่ลูกทุกตัวลง stack แล้วลืมว่า LIFO กลับลำดับ การวน iterator ตามลำดับที่กำหนดช่วยแสดงจุดนี้ชัดเจน

หน้า 21 เป็นภาพ DFS ของ 8-Puzzle ที่ระบุ depth bound = 5: ขอบเขตนี้เป็นส่วนของตัวอย่างนั้น ไม่ใช่คุณสมบัติของ DFS ทุก implementation และอาจตัดคำตอบที่ลึกกว่า 5 ทิ้ง DFS ในบทนี้เป็น graph search ไม่มี depth bound และไม่ได้อ้างว่า replay ลำดับเลขทุกตัวจากภาพหน้า 21

ค้นหาตามความกว้าง (Breadth-First Search: BFS)

หน้า 22–23: เลือกสถานะที่ตื้นก่อน ใช้ FIFO queue จึงสำรวจชั้นความลึกตามลำดับ หน้า 24 เป็นภาพกราฟประกอบ หน้า 26 ให้ pseudocode ที่ตรวจ goal ของ successor เมื่อสร้าง ส่วนโค้ดในบทนี้ตรวจเมื่อ dequeue เพื่อให้ trace มีจุดตรวจเดียว ผลคำตอบยังมีความลึกน้อยที่สุดเมื่อเงื่อนไขครบ แต่จำนวน node ที่สร้างก่อนหยุดอาจต่างกัน

หน้า 27 แสดงต้นไม้ BFS ของ 8-Puzzle เทียบกับ DFS หน้า 21 ให้สังเกตลำดับชั้นและ frontier ที่กว้างขึ้น ไม่ถือว่าหมายเลขในภาพเป็นลำดับที่ใช้กับกราฟตัวอย่างใหม่ทุกกราฟ

ข้อผิดพลาดที่พบบ่อย (Common Mistakes)

  • ใช้ pop() ท้าย list แล้วเรียกว่า BFS: ต้องนำหัว queue ออก เช่น deque.popleft()
  • บอกว่า DFS ลองตัวอักษรน้อยก่อน แต่ push A แล้ว B ลง stack ธรรมดา: B จะถูก pop ก่อน ต้องกำหนดกลไกให้ตรง trace
  • เรียกทุก state ที่ discovered ว่า expanded: BFS อาจมี D ค้างอยู่ตอนคืน goal
  • ใช้ tree search กับกราฟวงจรโดยไม่ตรวจซ้ำ: frontier อาจโตไม่สิ้นสุด
  • DFS mark ทุก sibling ว่า visited ก่อนลงกิ่ง แล้วอ้างว่าเหมือน recursive DFS: อาจเปลี่ยน discovery tree เมื่อมีขอบเชื่อม sibling ใช้ frame ที่เก็บจุดกลับมาอย่างในตัวอย่าง
  • อ้าง BFS สั้นที่สุดด้านระยะทางบนแผนที่ที่ cost ต่างกัน หรืออ้าง DFS เจอคำตอบแรกจึงดีที่สุด
  • ใช้แค่พิกัดเป็น state ทั้งที่โจทย์มีกุญแจ/พลังงานซึ่งมีผลต่อการเดินต่อ ต้องรวมข้อมูลที่จำเป็นนั้นใน state ด้วย
  • นำความซับซ้อนของ tree frontier ไปอ้างเป็นหน่วยความจำรวมของ graph search ที่เก็บ visited และ trace

3. Trace BFS และอธิบาย frontier

ใช้กราฟเดิม เหตุใด D อยู่ใน discovered แต่ไม่อยู่ใน visit order เมื่อจบ และทำไมเส้นทางไม่ผ่าน A?

เฉลย: visit S A B C G, queue หลัง C คือ [G,D] จึง dequeue G และหยุด D ถูกพบจาก C แต่ยังไม่ประมวลผล Parent ของ G คือ B ที่พบก่อน จึงย้อนเป็น S B G มี 2 ขอบ ไม่ใช้รายการ visit ทั้งหมดเป็นคำตอบเส้นทาง

4. วงจร กราฟที่ไปไม่ถึง และ backtracking

กำหนด X: (Y), Y: (X) เริ่ม X และหา Z ที่เข้าไม่ถึง ทั้งสองวิธีควรจบอย่างไร?

เฉลย: ทั้งคู่ visit X,Y เพียงครั้งเดียวและคืน None BFS queue หมด ส่วน DFS ข้าม X ที่พบแล้ว จากนั้น backtrack Y และ X จน stack ว่าง Tree search ที่ไม่ตรวจซ้ำอาจสร้าง X,Y,X,Y,... ไม่จบ ถ้า start เป็น goal อยู่แล้ว ทั้งสองคืน path [start] ทันที

5. จำนวนก้าวเทียบต้นทุน

กราฟใหม่มี S → G cost 9 และ S → A cost 1, A → G cost 1 กำหนดเพื่อนบ้าน S เป็น (G,A) BFS แบบไม่ใช้ weights จะได้คำตอบต้นทุนต่ำสุดหรือไม่?

เฉลย: BFS ได้ [S,G] เพราะลึก 1 มี cost 9 แต่ [S,A,G] ลึก 2 มี cost 2 ดังนั้นตื้นที่สุดไม่เท่ากับ least cost ในโจทย์นี้ โค้ดบทนี้ไม่ได้อ่าน weights และไม่ควรนำไปใช้รับรอง least cost หัวข้อต้นทุนที่ต่างกันต้องใช้อัลกอริทึมที่เหมาะสมซึ่งอยู่นอกบท

8. วิธีใดดีกว่า และ DFS ครบถ้วนเมื่อใด?

ตอบคำถามเปรียบเทียบหน้า 28–30 พร้อมเงื่อนไข ไม่อ้างว่า BFS หรือ DFS ชนะเสมอ

เฉลยเสริม: BFS เหมาะเมื่อ goal ตื้นและต้องการจำนวนน้อยก้าว แต่ frontier อาจกว้าง DFS อาจไปถึง goal ลึกเร็วถ้าอยู่กิ่งที่ลองก่อน แต่ถ้าอยู่กิ่งอื่นก็อาจช้ามาก กราฟจำกัดพร้อม visited ทำให้ DFS จบได้ แต่ต้นไม้ที่กิ่งแรกมี state ใหม่ต่อกันอนันต์ยังทำให้ไม่ไปถึง goal ในกิ่งถัดไป การกันวงจรไม่ได้แก้กิ่งอนันต์ที่ไม่วน และการกำหนด limit อาจตัด goal ออก

สรุปทบทวน (Quick Summary)

  • กำหนดแบบจำลองก่อนเลือกอัลกอริทึม State ต้องเก็บข้อมูลที่ทำให้ตัดสินการเดินต่อได้
  • Graph มี state เดียวต่อโหนด ส่วน search-tree node แทนเส้นทาง State จึงปรากฏซ้ำได้
  • BFS ใช้ FIFO หา goal ตื้นสุด; least cost ต้องมีต้นทุนบวกเท่ากันทุกขอบ
  • DFS ใช้ LIFO และ backtrack; ไม่รับประกันตื้นสุดหรือต้นทุนต่ำสุด
  • ระบุ successor order จุด mark discovered และจุดตรวจ goal ก่อนเขียน trace
  • กัน state ซ้ำเพื่อจัดการวงจร และระบุ finite/infinite, tree/graph และ trace overhead ก่อนอ้าง complexity
