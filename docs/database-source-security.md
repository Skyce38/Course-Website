# Database source security review

Baseline: `795152c2361a1f9c57309555a7383e7980b269df`. Original user files are read-only, outside this checkout. Public source metadata/hashes are in [the evidence inventory](../scripts/database-source-evidence.json); no machine-specific personal directory is published.

Both ZIPs were enumerated and checked for absolute/traversal paths and oversized members before reading. No unsafe paths were found. Only text sources were extracted into a private temporary audit directory. Images, photographs, `.env` and its variants were excluded; no configuration values or credentials are imported into the website. macOS resource forks are irrelevant to the curriculum. The supplied SQL/DOCX explicitly identify Campus Delivery records as simulated teaching data, not private student submissions.

`student.zip` contains sensitive environment-file names. `config/db.php` in each starter was reviewed as configuration, with its values withheld from logs and publication. New `.gitignore` rules exclude environment files, caches and local source/design directories. No original ZIP, PDF, workbook, photograph, private connection configuration or source extraction is a release asset.

Discovery did not execute imported PHP or SQL. The Campus SQL contains `DROP DATABASE`; both Resume setup scripts contain `DROP TABLE`. They must never be run against a user's existing database or Angsila. Validation uses independently authored fixtures in an explicitly isolated disposable database, after review; it does not invoke the supplied destructive scripts. Every executable test must name its engine/version and its isolated target. Portable authoring tools, if used, remain outside Git and are not website dependencies.

The public instructor repository was read at the pinned commit in the inventory. Login/logout are intentionally incomplete. Its CRUD SQL is already filled in even though TODO comments remain; comments alone are not proof of missing implementation. In contrast, the local `student.zip` still has four `SELECT 1` SQL placeholders. It chooses the first demo profile and has no user authentication. Its CSRF tokens and prepared statements do not establish record ownership for a real multi-user deployment.

No remote instructor repository, existing MySQL account or Angsila resource is modified during authoring. This release provides static lessons and assessment only; it does not deploy a PHP/SQL executor or authentication service. New harmless accounts and credentials used by disposable tests are not university accounts. Final publication checks scan intended files for source credentials/private paths and compare all eight original file hashes and protected-worktree snapshots; results are recorded in [QA](database-qa.md). Only the requested Course-Website feature branch and PR are published after review.
