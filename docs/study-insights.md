# Study Insights — Phase 11

`insights.html` is a read-only, client-side view of existing Practice Mode and Extended Exam results. Modern homepage navigation links to it; the same page also supports Classic. No Learning Paths, account, tracking service, upload or mastery model is introduced.

## Exact measurement rules

- **Included result:** a supported version/revision with valid responses and every automatically graded question in its selected run submitted. A partially answered automatic run is excluded, not extrapolated. Unsubmitted drafts never count. Self-only topic runs need at least one submitted self-assessment and contribute no automatic observations.
- **Correctness:** recomputed from raw drafts using `PracticeContract.grade`, including its exact/tolerance-based numeric policy. Ignore any persisted score/correctness fields. Practice uses its own original revision; Exam runs require a valid configuration token, mode, selected IDs/count/topic and the current bank revision.
- **Accuracy:** `correct / (correct + incorrect)` automatic observations. Show an em dash for an empty denominator. Course and topic values use the same formula. Self-assessments are excluded from accuracy and unique graded-question counts.
- **Repeated vs unique:** separate saved attempts, including repeated answers across different sessions, are real observations. Unique automatic questions use stable lesson/question identities; repeated observations equal automatic observations minus unique automatic questions. Original Practice questions also appearing in Exam count once in the unique inventory, while genuinely separate runs remain observations.
- **Deduplication:** within a run, duplicate saved records with identical timestamp/submitted responses count once. A completed active response snapshot identical to its latest valid saved attempt counts once, regardless of the `recorded` flag or object property order. Separate saved repeats at different timestamps remain observations. Storage cannot distinguish every possible unsaved restart with identical answers; the conservative equality rule may suppress such an active snapshot.
- **Self-assessment:** submitted `revisit` ratings are separate ungraded observations in included results; repeated ratings can appear more than once. They do not establish objectively measured knowledge. The Revisit section never displays a self-assessment grade.
- **Review priority:** only topics with actual incorrect observations appear. Default order: incorrect count descending, accuracy ascending, then stable lesson/heading ID. Alternative orders: lowest accuracy or lesson/topic title. Repeated attempts can dominate mistake counts; this is disclosed.
- **Limited sample:** fewer than three distinct automatic questions **or** five automatic observations. This is an explicit display convention, not a validated confidence/mastery threshold. Some topics have fewer than three automatic bank questions and remain limited even after many repetitions. No progress/mastery is inferred from the presence or absence of a badge.
- **Topics/links:** use the bank's existing real heading references, including broad practice headings. There is no inferred semantic retagging. Every topic links to its source lesson section and Exam Mode. Practice links appear only when the original six-question Practice bank contains that topic. Exam links open the existing topic selector; they do not create a new session automatically.
- **Recent activity:** latest ten included results by saved-at timestamp; undated completed active snapshots appear last and explicitly say that no time is available. Saved-at is not an inferred answer/reading time. Links open the existing lesson mode, without automatically selecting a past session or creating a new one. Lessons practiced counts distinct lessons with included observations or submitted self-assessments.

## Historical context and exclusions

Archived Exam revisions never enter current metrics: validate their configuration against its frozen context, count each archived session once across live/backup configurations, but **do not read or regrade its run answers**. A visible notice directs users to the original reader for archived context. Unknown/future revisions, invalid IDs/configurations, malformed payloads and incomplete records are separately reported. Valid attempts in a container can survive an unrelated invalid attempt; an incompatible container is excluded entirely.

Only registered lesson namespaces and explicitly configured sessions are read. Orphan run keys cannot reliably reconstruct a run and are not searched/recovered. Current storage retains at most ten saved attempts per run and ten selectable sessions per lesson per revision; the dashboard cannot reconstruct evicted or missing history. Exclusion counts describe records/configurations examined, not a count of discarded answers or a lifetime log. They cover the complete read, while the course filter applies to displayed included results.

## Storage/privacy and performance

`InsightsContract` has no mutation API. It receives a getter, reuses existing pure contracts and never calls `setItem`, `removeItem` or `clear`. Dashboard scripts do not load `study.js`, `practice.js`, `exam.js` or migrations. Existing schema ownership and keys are unchanged.

The preferences script has a page-only `data-read-only` option: suppress both legacy System-mode persistence and user-triggered writes while applying appearance/language in memory. Insights shows this limitation clearly. Other pages keep their existing preference persistence; the preference schema/export format is unchanged.

Refresh on entry, explicit Refresh, BFCache restoration, returning visibility and relevant storage events. No polling. Raw JSON parsing is cached by exact key/value with a 512-key bound; summaries are cached per result/course so theme/language changes do not reparse or regrade answers. A storage read failure displays a warning; an invalid/unavailable answer manifest shows no metrics, with an explicit retry.

`scripts/insights-build.cjs` deterministically derives `assets/insights-banks.json` from registered reader banks plus original Practice identities. It preserves current/frozen grading contexts, validates with the shared contracts and includes no local teaching documents or learner data. Only Insights downloads this public file. Generated question data is not a new authoring source; edit the existing source banks through their established versioning process.

Approximate payload: manifest 676,211 bytes / 110,075 gzip bytes; dashboard JS/CSS/contracts roughly 8 KB gzip combined, plus the existing shared grading modules. Shared bilingual strings add 2,317 gzip bytes; the opt-in preference guard adds 48 gzip bytes. No chart library, image or font dependency. Sizes are local compression measurements, not production transfer/latency claims.
